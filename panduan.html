1 Overview Sistem CRM

Apa itu CRM Findest, komponen utama, dan philosophy nya

CRM Findest adalah sistem terintegrasi buat manage Sales, Konsinyasi, Inventory, Finance, dan Investor Reporting. Semua data di satu database (Supabase), semua channel (CRM admin, Catalog customer, Order Monitor, Investor Dashboard) share data yang sama.

Model Pricing

💡 HPP-based markup: Di catalog CRM, isi HPP (harga beli). Sistem otomatis kasih markup berdasarkan siapa yang scan QR:
• FnB customer (markup 12%) → HPP × 1.12
• Konsi partner (markup 24%) → HPP × 1.24
• Public visitor (default markup 20%) → HPP × 1.20 (biar HPP ga bocor)

2 Setup Awal (Sekali Doang)

Checklist sebelum tim mulai pake CRM

SQL Migrations di Supabase (WAJIB, urut)

Phase 2-10: setup dasar (biasanya udah applied)
Phase 11 archive-detail: backup detail sebelum reset
Phase 12 retur-konsi: RPC retur_from_konsi()
Phase 14 auto-konsi: trigger auto-add konsi dari scan QR
Phase 15 markup: kolom customers.markup_pct
Phase 17 realtime: enable realtime buat investor dashboard
Phase 4B Fonnte: notify order baru via WA (butuh Fonnte token di config)
Phase 19 auto-sync Lunas + reminder: auto-payment saat invoice Lunas, auto-WA no_invoice ke customer, cron reminder H+1/H+7/H+14
⚙️ Setup pg_cron (buat Phase 19):
Sebelum run Phase 19, enable extension pg_cron dulu di Supabase Dashboard → Database → Extensions → search "pg_cron" → Enable. Kalo lupa, seluruh SQL Phase 19 tetep jalan tapi cron ga aktif (harus manual panggil SELECT public.send_overdue_reminders();).
💡 Cek status migration:
SELECT
  EXISTS(SELECT 1 FROM information_schema.tables WHERE table_name='orders_archive') AS phase11,
  EXISTS(SELECT 1 FROM information_schema.routines WHERE routine_name='retur_from_konsi') AS phase12,
  EXISTS(SELECT 1 FROM information_schema.triggers WHERE trigger_name='trg_auto_konsi_from_order') AS phase14,
  EXISTS(SELECT 1 FROM information_schema.columns WHERE column_name='markup_pct') AS phase15;

3 Case: Order & Sales

Skenario penerimaan order + pemrosesan
Case 3.1: Customer FnB scan QR → order dari catalog
Skenario: Alive Vana (F&B, markup 12%) scan QR mereka → catalog buka → pilih 3 BSN Syntha 5lb → checkout Termin 30 hari
1
Customer scan QR di HP → catalog auto-open dengan banner "Halo, Alive Vana" + markup 12%
2
Add produk ke cart → checkout → pilih Termin 30 Hari
3
Sistem cek stok latest (guard race condition) → kirim WA ke sales + save ke orders
4
Order muncul di Order Monitor — admin cek + ubah status ke "Selesai"
5
Trigger phase 6 auto-generate invoice di Finance → Invoice tab
6
Admin klik 🖨️ Faktur → print A4 (ED + batch otomatis dari data batches)
✅ Result: Order tersimpan, invoice auto, faktur ready buat kirim. Customer bisa lacak via link ?o=ORDER_ID
Case 3.2: Customer overdue scan QR → popup pengingat tagihan
Skenario: 71Gym punya invoice FKT-73 lewat jatuh tempo 12 hari, mereka scan QR mau order lagi
1
71Gym scan QR → catalog load → sistem cek invoice belum lunas + jatuh tempo lewat
2
Popup otomatis muncul: "⏰ Pengingat Tagihan" dengan list invoice overdue + total
3
Tombol 💬 Konfirmasi via WhatsApp — auto-generate message ke sales dgn detail invoice
4
Atau tombol "Nanti aja, lanjut belanja" (dismiss session)
✅ Result: Soft-collection tanpa WA broadcast agresif. Customer sadar sendiri, ada pilihan konfirmasi langsung.
Case 3.3: Admin buat order manual (customer telfon/datang langsung)
Skenario: Customer datang ke gudang, admin input order manual (bukan via catalog)
1
Sales → Orders → + Tambah Order
2
Isi customer (auto-suggest), produk, total, pembayaran, sales PIC
3
Simpan → status default "Proses" → kalo sudah kirim, ubah ke "Selesai"
4
Auto-invoice generated → print faktur

4 Case: Konsinyasi

Titipan barang ke partner, retur, transfer ke customer FnB
Case 4.1: Konsi partner scan QR → auto-titipan tercatat
Skenario: Sunset Farma Group (perwakilan konsi) scan QR mereka → order 15 unit produk dari catalog. Ini bukan "jual", tapi "titip" ke sana.
1
Sunset Farma Group scan QR → catalog buka dengan banner UNGU "🔄 TITIPAN KONSI"
2
Add produk → checkout → tombol jadi "Konfirmasi Titipan"
3
Submit → order tersimpan di orders dgn channel="Konsinyasi (Titipan)"
4
Trigger phase 14 auto-fire: insert row di konsinyasi per produk dengan outlet=Sunset Farma, qty, harga, ED (auto dari batches FIFO)
5
CRM → Sales → Konsinyasi → row baru muncul di tab tsb, badge "🔄 TITIPAN KONSI" di Order Monitor
✅ Result: Single entry via scan QR = order + konsi auto-populate. Ga perlu manual "+ Catat Konsinyasi" lagi.
Case 4.2: Retur barang dari konsi → balik ke gudang FP
Skenario: Barang di Sunset Farma udah 60 hari, ED deket, mau ditarik balik ke gudang FP
1
Sales → Konsinyasi → view Tabel → cari row Sunset Farma yg mau diretur
2
Klik 🔁 Retur di kolom Aksi
3
Isi qty retur, tanggal, tujuan: 🏭 Masuk Gudang FP, alasan
4
Submit → RPC atomic: konsi qty_retur ↑, products.stok ↑, batches baru (ED sama), log ke konsi_returns
✅ Result: Stok balik ke FP, ED info ke-preserve, semua tercatat rapih buat rekonsiliasi.
Case 4.3: Order dari Konsi → transfer barang ke customer FnB langsung
Skenario: Customer FnB minta WGS 10lb, tapi gudang FP habis. Sunset Farma masih ada 5 unit titipan. Tarik dari sana → langsung ke FnB (bukan mampir gudang).
1
Sales → Konsinyasi → klik tombol 🚀 Order dari Konsi (kuning)
2
Pilih customer FnB tujuan → payment method (Termin 3/7/30 hari)
3
Search produk → pilih dari list konsi partner (multi-partner OK) → add ke cart
4
Kalo mau reprice ke markup customer FnB: klik 🎯 Reprice ke Markup (auto HPP × markup_pct)
5
Atau adjust manual per line di input harga (kalo mau kasih diskon khusus)
6
Klik 🚀 Buat Order + Faktur
7
Auto: konsi partner qty_retur ↑, order OFK-xxx tersimpan, invoice auto-generate, faktur otomatis kebuka
✅ Result: 1 klik, no selisih akhir bulan. Konsi partner tau barang berkurang, customer FnB dapet order + faktur, gudang FP ga di-touch (barang langsung transfer).
Case 4.4: Rekonsiliasi konsi akhir bulan
Skenario: Akhir September, perlu cocokin data konsi CRM dgn SO fisik di Sunset Farma
1
Sales → Konsinyasi → filter outlet=Sunset Farma Group, filter bulan=Sep
2
Buka 📜 History Retur — liat total retur bulan itu ke gudang FP
3
Datangi Sunset Farma → hitung fisik SO → catat qty aktual sisa
4
Edit tiap row konsi → update qty_terjual dan qty_retur aktual → ubah status ke Rekonsiliasi atau Lunas
5
Kalo ada selisih (barang hilang / rusak) → catat di catatan row tsb
✅ Result: Data CRM match SO fisik. Ga bakal kecolongan 200jt kaya sebelum ada sistem 🎯

5 Case: ED Alert (Barang Mau Expired)

Cegah loss dari barang expired
Case 5.1: Monitor produk deket ED tiap Senin pagi
Skenario: Rutin Monday morning cek barang mau ED, action segera
1
Dashboard → scroll ke ⚠️ ED Alert Watchlist card
2
List produk mau ED muncul dgn: outlet lokasi, produk, sisa qty, hari sampai ED
3
Klik 💬 WA Partner — auto message ke PIC partner: "Boss, sisa X unit ED tgl Y, tolong push jualan"
4
Kalo mau tarik ke gudang: pergi ke Konsinyasi tab → 🔁 Retur ke Gudang FP
5
Kalo mau transfer ke FnB langsung: pake fitur 🚀 Order dari Konsi
✅ Result: ED loss dari 200jt/tahun bisa turun drastis kalo consistent tiap Senin.
💡 Golden Rule ED Management:
• 90 hari sebelum ED: Push sales, notif ke PIC partner
• 60 hari sebelum ED: Transfer ke konsi partner dgn margin lower
• 30 hari sebelum ED: Flash sale broadcast ke B2C customer
• <15 hari: Bundle dengan produk fast-mover (contoh: WGS + Amino Energy 50% off)

6 Case: Finance & Kas

Payment, pengeluaran, rekap kas bulanan
Case 6.1: Customer transfer & konfirmasi bayar (1 klik = auto-sync)
Skenario: Customer WA Nadya "Kak, ini bukti transfer INV-2611-045 udah lunas ya". Nadya buka CRM, cari no faktur, klik ✅Lunas.
1
Finance → Invoice → di search box paling atas, ketik INV-2611-045 (atau ketik nominal kalo customer lupa cantumin, misal 12500000)
2
Klik ✅Lunas di baris invoice → konfirmasi
3
Otomatis:
  • Invoice status = Lunas, tgl_lunas = hari ini
  • Payment record auto-create ke tabel payments (metode Transfer)
  • Kas Masuk di Rekap Kas naik segitu
  • Piutang Outstanding turun
  • Investor Dashboard update realtime
✅ Result: 1 klik, 5 hal ke-sync. Ga perlu double input ke Payment. Angka Rekap Kas = angka mutasi bank Findest = balance.
Case 6.2: Auto-Reminder Fonnte (customer overdue di-WA otomatis)
Skenario: Setiap hari jam 9 pagi WIB, sistem scan invoice overdue → auto-kirim WA reminder ke customer via Fonnte. Ga perlu Nadya nagih satu-satu.
1
Tier 1 (H+1) — invoice lewat 1 hari → reminder halus ke customer
"Halo, Invoice INV-XXX lewat jatuh tempo 1 hari, mohon konfirmasi ya. Cantumkan No Faktur INV-XXX saat kirim bukti transfer."
2
Tier 2 (H+7) — lewat 7 hari → follow-up ke customer + CC WA ke Fazar
Fazar tau siapa yg mulai bandel bayarnya.
3
Tier 3 (H+14) — lewat 14 hari → warning ke customer + CC ke Fazar
Fazar bisa ambil action langsung (nelpon, kunjungi outlet, dll).
4
Anti-spam: tiap invoice max 1x per tier. Sekali dikirim T1, ga akan dikirim T1 lagi walau overdue makin lama — nunggu naik ke T2.
5
Cek badge di Invoice list: baris invoice yg udah kena reminder ada tag 🔔T1 / 🔔T2 / 🔔T3
6
Manual override 🔔Ingatkan: kalo Nadya liat ada overdue dan pengen langsung nagih (ga nunggu jam 9 pagi), klik tombol 🔔Ingatkan di baris invoice → pesan WA langsung terkirim ke customer saat itu juga.
✅ Result: Nadya ga perlu nagih customer 1-1. Fazar ga perlu monitor manual — cukup respons kalo dapet CC tier 2/3. Ada juga opsi manual kalo urgent.
Case 6.3: Order Termin baru → auto-WA no_invoice ke customer
Skenario: Sales input order Termin 30 hari. Sistem auto-create invoice → langsung kirim WA ke customer dgn No Faktur besar — biar customer bisa cantumin saat kirim bukti bayar nanti.
1
Sales/customer bikin order pembayaran Termin 30 Hari
2
Sales klik Selesai di order → auto-create invoice
3
Fonnte auto-kirim WA ke customer:
"Order kamu sudah masuk sistem. No Faktur: INV-2611-045. Total Rp 12.500.000. Jatuh Tempo 26 Des 2026. Mohon simpan No Faktur ini — dipakai saat kirim bukti transfer nanti."
✅ Result: Customer paham dari awal harus cantumin no faktur. Nadya kerja gampang saat rekonsiliasi.
Case 6.4: Input pengeluaran (gaji, sewa, ops, dll)
1
Finance → Pengeluaran → + Tambah
2
Isi kategori (Gaji, Sewa, Bensin, Ops, Marketing, dll), tanggal, nominal, keterangan
3
Simpan → auto muncul di Rekap Kas keluar
Case 6.5: Rekap Kas bulanan (closing + balance vs rekening BCA)
1
Finance → Rekap Kas → pilih bulan → klik Tampilkan
2
Isi Kas Awal Bulan (saldo akhir bulan lalu) → Simpan
3
Verifikasi angka:
  • Total Kas Masuk (payment auto-sync dari invoice Lunas)
  • Total Kas Keluar (semua expenses)
  • Saldo Akhir = Awal + Masuk − Keluar
  • Piutang Outstanding (invoice belum lunas)
4
Cocokin sama mutasi rekening BCA Findest — kalo selisih, cek transaksi mana yg missing (mungkin ada invoice belum di-mark Lunas, atau expense belum diinput)
5
Kalo aman, Dashboard → 💾 Snap Now → save snapshot bulan tsb
✅ Result: Closing bulan clean, angka CRM = angka bank, snapshot tersimpan di History Bulanan, siap buat report investor.

10 FAQ & Troubleshooting

Masalah umum + solusi cepat

❓ Order/Login

ProblemSolusi
Order dari catalog gak muncul di CRMRefresh Order Monitor (↻ button), cek internet
Login CRM gagal / tombol Masuk stuckHard refresh (Ctrl+Shift+R), clear browser cache
Order Monitor: PIN salahDefault findest2024, atau cek Settings → PIN admin

❓ Konsi

ProblemSolusi
Konsi partner scan QR, gak masuk ke tab KonsinyasiPastikan customer.sistem='Konsinyasi'. Trigger phase 14 perlu applied.
Retur error: "function not found"Phase 12 SQL belum applied. Run di Supabase.
Order dari Konsi: harga default terlalu tinggiKlik 🎯 Reprice ke Markup — auto-sesuaikan sama markup customer

❓ Faktur / Print

ProblemSolusi
ED column di faktur kosongPastikan batches tsb udah input dgn ED date. Sistem auto-fetch FIFO.
Faktur multi-item ga muat 1 halamanSistem auto-compress kalo 9+ items. Kalo tetap ga muat, adjust manual.
Pop-up blocked saat print fakturAllow pop-up di browser settings buat findestsport.github.io

❓ Investor Dashboard

ProblemSolusi
PIN salah walau udah benerCek Settings → Investor PIN, save Semua, hard refresh investor.html
Data ga live updatePhase 17 realtime SQL belum applied
Badge LIVE jadi kuning "RECONNECTING"Cek internet investor. Auto-reconnect pas online.

❓ Markup / Harga

ProblemSolusi
Harga di catalog ga sesuai markup customerSales → Customer → edit tsb → set markup_pct
Public catalog (tanpa QR) tampil HPPSettings → Catalog Default Markup, isi 20% (biar HPP ga bocor)
Nominal input tanpa titik ribuanSistem auto-format saat ngetik. Kalo ga jalan, hard refresh.
🚨 Emergency — kalo sistem down / error blocker / data missing → screenshot + kirim ke tech tim.
